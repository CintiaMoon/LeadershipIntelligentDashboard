# DTO to view mapping (executive dashboard)

Types are generated from the backend OpenAPI document (`npm run gen:api` -> `src/types/api.d.ts`). The OpenAPI document leaves the free-form JSON parts (patterns, penalties, imbalances, dimension details) untyped, so those are validated once at the boundary with zod schemas in `src/types/views.ts`; an unexpected shape becomes a clear error state, never a blank screen. JSON examples are in `src/tests/fixtures.ts` (captured from the real API). The frontend shows backend values and never calculates scores, penalties, confidence or severity (ESLint rule `no-restricted-syntax`).

| View / component | Endpoint(s) | Backend fields used | Notes |
|---|---|---|---|
| `LisHero` | `GET /scoring-runs/{id}`, `/catalog`, dashboard summary, `/trends` | `leadershipIntelligenceScore`, `interpretation`, `calculatedAt`, `notice`; catalog `lisBands`; summary `previousScore`, `change`, `comparable`, `notComparableReasons`; trend points' `run.leadershipIntelligenceScore` | change shown only when `comparable` (D27); band range from the catalog |
| `ScoreGauge` | catalog `lisBands` | `label`, `min`, `max` | positioning only (`percentOf`, `bandSpan`) |
| `DimensionCard` | run `dimensions[d]`, `/dimensions`, `/catalog`, `/compare`, `/trends` | `adjustedScore`, `rawScore`, `effectivePenalty`, `label`, `status`, `coverage`; details `score.contributions[]`; compare `dimensions[].change`; trend `dimensions[].adjustedScore` | name and description from the catalog; contributions hidden (redacted) for VIEWER |
| Risk indicator (card) | `/patterns`, `/penalties` | pattern `category`, `severity`, `status`; penalty `target`, `status` | counts and highest severity of detected patterns |
| `RiskOverview` | `/patterns` | `severity`, `status = MATCHED` | filter kept in the address (`?severity=`) |
| `PatternOverview` / `PatternCard` | `/patterns`, `/catalog`, `/recommendations`, `/penalties` | `patternId`, `code`, `category`, `severity`, `status`, `reason`, `confidence`, `confidenceBand`, `evidence[]`, `actionKeys`; catalog `patterns[id]`; recommendation titles by key; penalties' `target` for affected dimensions | grouping by dimension, severity or confidence; INELIGIBLE patterns kept apart as "not enough evidence" |
| `EvidenceList` | `/patterns` | `evidence[].operandKey`, `numericValue`, `flag`, `reliability`, `sourceQuestionIds`; catalog `signals`, `questions` | values absent for VIEWER; shows the items only |
| `PenaltyOverview` / `PenaltyCard` | `/penalties`, `/catalog` | `penaltyId`, `status`, `reason`, `target`, `candidateDeduction`, `effectiveDeduction`, `suppressedAmount`, `winningPenaltyId`, `stackingPolicy`, `triggerPatternId`, `effectiveByTarget` | four states only (D7); suppressed always shown; not-triggered behind a disclosure |
| `RecommendationsPanel` | `/recommendations` | `recommendations[]` (`key`, `title`, `description`, `severity`, `sources[]`), `unmappedActionKeys` | order as returned; each action links to the pattern behind it |
| `TrendsSection` | `/organizations/{id}/trends` | per point: `run` summary, `dimensions[]`, `patterns[]`, `patternsBySeverity`, `penalties` | banner and chart markers wherever `comparable = false` with reasons (D27) |
| `ScopeSwitcher` | run `teamRuns[]` | `teamId`, `scoreStatus` | lists teams by identifier and marks those without enough responses; shows no score; the choice lives in the address (`?team=`) |
| `ResponsesPanel` | run `responses` (validated in `src/types/views.ts`) | `questions[]` (`scope`, `method`, `respondents`, `participation`, `usedAnswers`, `minimum`, `belowMinimum`), `unscoredTeams` | counts and the method only, never an answer; a group below the minimum is explained |
| `SourceAnswers` | `GET /scoring-runs/{id}/answers` | per question `scope`, `answer`, `teamId`, `declaredRespondents`, or for members `count`, `values` (sorted), `suppressed` | member answers only as a group; a suppressed group shows its count only |
| `VersionInfo` | run | `engineVersion`, `algorithmVersion`, `configurationVersion`, `configurationHash`, `scoringRunId`, `calculatedAt`, `scope`, `teamId` | |
| `ExplanationPage` / stages / `Waterfall` | `GET /scoring-runs/{id}/explanation` | trace `header`, stages `NORMALIZATION`, `SIGNALS`, `RAW_DIMENSIONS`, `PATTERNS`, `PENALTIES`, `ADJUSTED_DIMENSIONS`, `OVERALL` (validated in `src/types/trace.ts`) | stages absent for VIEWER are shown as hidden; waterfall bars use each stored value only, earlier values are laid out as invisible spacers (no sums) |
| `DimensionDetailPage` | `/dimensions`, run, `/trends`, `/compare`, `/answers`, `/patterns`, `/penalties`, `/recommendations`, `/catalog` | contributions, `positiveDrivers`, `negativeDrivers`, comparison `dimensions[].change`, answers | answers requested only for OWNER/ADMIN/ANALYST |
| `PatternDetailPage` / `ConditionTree` | `/patterns`, `/penalties`, `/recommendations`, `/catalog` | `conditionResult` tree (leaf `detail` rewritten with display names), `evidence`, `confidenceBreakdown`, `missingOperands` | related = same category or shared evidence |
| `PenaltyDetailPage` | `/penalties`, `/patterns`, `/catalog` | candidate, effective, suppressed amounts, `stackingPolicy`, `winningPenaltyId`, `effectiveByTarget` | maximum deduction not available (D42) |
| `ComparePage` | `/scoring-runs/compare`, `/scoring-runs` (picker) | `comparable`, `notComparableReasons`, both summaries, dimension changes, pattern lists | change shown only when comparable |
| Organization list | access token | `org_ids`, `roles`, `tenant_id` | decoded only to shape the UI; the backend enforces access |
| `TenantListPage` | `GET /platform/tenants` | `items[]` (`id`, `name`, `createdAt`) | platform administrator only; the query is disabled for everyone else; the filter is client-side over the returned list |
| `CreateTenantPage` | `POST /platform/tenants` | body `{id, name}`; 201 tenant, 409 taken id, 422 not allowed | the same id rule as the backend is checked first; a taken id is shown on the id field |
